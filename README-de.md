Batuk ist ein Open-Source-Workspace für Enterprise AI, für Organisationen, die kontrollieren wollen, wo AI läuft, welche Modelle Benutzer verwenden dürfen, wie Dokumente abgerufen werden und wie Nutzung gesteuert wird. Batuk kombiniert eine ausgereifte Multi-Modell-Chat-Oberfläche mit privatem RAG, Team-Workspaces, Microsoft Entra ID / Azure AD SSO-fähiger Identität, Audit-Workflows, Token-Nutzungsberichten und OpenAI-kompatiblen internen APIs.

Batuk funktioniert als lokal orientierter souveräner AI-Chat-Workspace für einzelne Teams und als selbst gehostete AI-Plattform für größere Organisationen. Es kann auf einem Laptop mit lokalem Speicher laufen, mit Docker bereitgestellt werden, SQL-Datenbanken und Vektorspeicher anbinden oder in einer kontrollierten Enterprise-Umgebung betrieben werden, in der Modell-Zugangsdaten, Dokumente, Memories und Audit-Nachweise unter dem eigenen Betriebsmodell bleiben.

## Warum Batuk

Batuk ist für Teams gebaut, die mehr brauchen als einen Chatbot. Administratoren erhalten eine zentrale Steuerungsebene für AI-Zugriff, Dokumente, Workspaces, Modell-Routing, API Keys, Compliance-Nachweise und Organisationsbranding.

Batuk ist eine starke Wahl für private Enterprise-AI-Workspaces, weil Souveränität als Produktanforderung behandelt wird. Lokale Modelle, gehostete Frontier-Modelle, private Modell-Gateways, Dokumenten-RAG, Identität, Autorisierung, Audit Trails, Nutzungsübersicht und Workspace-Grenzen sind so entworfen, dass sie in derselben Oberfläche zusammenarbeiten.

- **Souverän by design:** Lokale Modelle, gehostete Anbieter oder private OpenAI-kompatible Endpunkte nutzen, während Benutzer-, Dokument-, Memory- und API-Zugriff unter Admin-Kontrolle bleiben.
- **Enterprise-ready Workspace:** Benutzer, Admins, Organisationen, Teams, geteilte Workspaces, Microsoft Entra ID / Azure AD SSO, OAuth/OIDC, SAML, SCIM und geschützte Produkt-APIs sind Teil der Plattform.
- **Private Dokumentenintelligenz:** Dokumente hochladen, Text extrahieren, Inhalte chunking-fähig machen, Vektoren erzeugen, Quellen abrufen und RAG nach Benutzer, Organisation oder geteiltem Workspace begrenzen.
- **Modellauswahl ohne Chaos:** Admins entscheiden, welche Anbieter und Modelle verfügbar sind; Benutzer erhalten eine klare Chat-UI mit Provider Settings, Modellauswahl, Sprache, Websuche und Guardrails.
- **Internes AI API Gateway:** Freigegebene Modelle über Batuk API Keys und OpenAI-kompatible Endpunkte für interne Tools, Agents und Produktintegrationen bereitstellen.
- **Compliance-bewusster Betrieb:** Audit Logs, GDPR-Workflows, Control Register, Nutzungsberichte und CSV-Nachweise helfen Teams, AI-Aktivität zu verstehen und zu steuern.
- **Flexible Selbsthosting-Optionen:** Mit lokalem JSON/SQLite starten und später auf PostgreSQL, MySQL, ChromaDB, Pinecone, Qdrant Cloud, Supabase, Docker und optionale Advanced-RAG-Services erweitern.
- **White-Label Workspace:** Organisationen können Produktname, Tagline, Akzentfarbe, Initialen und Logo setzen, während die Creator Attribution erhalten bleibt.

## Plattformfunktionen

### Souveräner Multi-Modell-Chat

Batuk bietet einen privaten AI-Chat-Workspace, in dem Admins lokale Inferenz, Cloud-LLMs, Routing-Anbieter und eigene Modell-Gateways über eine zentrale Provider Registry aktivieren können.

- Streaming Chat mit Markdown-Rendering.
- Provider-Modellauswahl und manuelle Modelleingabe.
- Runtime Settings für lokale Evaluierung und serverseitige Konfiguration über Umgebungsvariablen.
- Temporärer Chat-Modus für Gespräche, die nicht gespeichert werden sollen.
- Persönliche und geteilte Workspaces mit Ordnern, Suche, Import, Export und Kopieraktionen.
- OpenAI-gehostete Websuche, wenn aktiviert und vom gewählten Modell unterstützt.
- OpenAI Realtime und Grok Voice Sessions mit Browser-Mikrofon.
- Guardrails für sichereres Prompt-Screening und Systemverhalten.
- Workspace-Tools für Provider Settings, API-Zugriff, Workspace-Management, Chat-Historie, Token-Nutzung, Enterprise Management und Audit Review.

### Document Chat und Enterprise RAG

Batuk macht interne Dokumente zu bereichsgebundenem AI-Kontext. Persönliche Dateien bleiben persönlich. Geteiltes Workspace-RAG ist nur für zugewiesene Mitglieder und Admins sichtbar.

- PDF-, TXT-, Markdown-, JSON-, LOG-, CSV-, XLS-, XLSX- und DOCX-Dateien hochladen.
- Text extrahieren, Inhalte chunking-fähig machen, Embeddings erzeugen und relevante Kontexte im Chat abrufen.
- Lokale deterministische Embeddings, direkte Ollama `/api/embed` Embeddings, LlamaIndex Ollama Embeddings oder gehostete OpenAI Embeddings nutzen.
- Ollama RAG unterstützt jedes lokal gepullte Embedding-Modell, darunter `embeddinggemma`, `qwen3-embedding`, `all-minilm`, `nomic-embed-text`, `mxbai-embed-large` und eigene Ollama Embedding-Modelle.
- Batuk erkennt Vektordimensionen aus jeder Embedding-Antwort, statt eine feste Größe zu erzwingen; Ollama-Dimensionen hängen vom Modell ab, OpenAI `text-embedding-3-small` nutzt standardmäßig 1536, `text-embedding-3-large` kann 3072 nutzen, lokale deterministische Embeddings verwenden 384.
- Vektoren in lokalem JSON, ChromaDB, Pinecone, Qdrant Cloud oder Supabase Postgres/pgvector speichern.
- Organisations-, Benutzer- und Workspace-Metadaten auf Chunks und Vektoren bewahren.
- Dokumente im Documents Workspace neu indexieren, herunterladen und löschen.
- Metadaten, Quelldateien, Chunks und Remote-Vektoren beim Löschen entfernen, soweit der gewählte Vektorspeicher dies unterstützt.

### Advanced RAG und Graph Intelligence

Batuk läuft auch ohne Python. Für tiefere Dokumentenintelligenz ergänzt ein optionales FastAPI-Backend Advanced Extraction, Graph RAG und lokale ML-Guardrails.

- Komplexe PDF-Extraktion für Tabellen, gescannte Seiten, mehrspaltige Layouts, Seitenmetadaten, Abbildungen, Reports und wissenschaftliche Dokumente.
- Strukturerhaltende Ausgabe für Dokumente, Seiten, Abschnitte, Absätze, Tabellen, Abbildungen, Chunks und Zitationen.
- Graph-RAG-Ingestion mit Entity Extraction, Relationship Extraction, Community Detection, Graph-Visualisierungsdaten und optionaler Neo4j-Persistenz.
- LLM-basierte Graph Extraction über einen konfigurierbaren OpenAI-kompatiblen Endpunkt.
- Lokales Dokumentenscanning für PII, Secrets, Sprache und Sensitivität.
- Seitenbewusste Chunks und reichere Quellenkontexte für Document Chat.

### Enterprise Identity und Access Control

Batuk bringt Enterprise-Identity-Grundlagen über Better Auth Integrationen und geschützte API-Routen mit.

- E-Mail/Passwort-Authentifizierung.
- Admin-Management für Benutzer, Rollen, Bans, Passwort-Resets und Admin APIs.
- Organisationen, Teams, Mitglieder, Einladungen und Organisationsrollen.
- OAuth 2.1/OIDC Provider Mode mit Consent Page.
- One-click Microsoft Entra ID / Azure AD SSO über Umgebungsvariablen für Unternehmen, Universitäten und Microsoft-365-intensive Organisationen.
- SSO-Unterstützung für Enterprise OIDC/SAML Sign-in.
- SCIM Provisioning für Identity-Provider-Workflows.
- Geschützte APIs für Chat, Dokumente, Skills, Agents, Nutzung, Memory, Modelle, Attachments, Realtime Sessions, Workflows und Enterprise Operations.

### Microsoft Entra ID / Azure AD SSO

Batuk unterstützt Microsoft SSO für Organisationen, die auf Microsoft 365, Entra ID, Azure AD, Teams, Outlook, SharePoint und Microsoft-Tenants von Universitäten standardisieren. Admins können einen One-click `Continue with Microsoft` Login-Button über `.env` oder `.env.enterprise` aktivieren, ohne eigenen Auth-Code zu schreiben.

Erstelle eine Microsoft Entra ID App Registration und füge für lokale Entwicklung diese Redirect URI hinzu:

```text
http://localhost:3000/api/auth/sso/callback
```

Für Produktion ersetze den Host durch deine bereitgestellte `BETTER_AUTH_URL`:

```text
https://your-batuk-domain.com/api/auth/sso/callback
```

Dann setzen:

```env
BATUK_MICROSOFT_SSO_ENABLED=true
NEXT_PUBLIC_BATUK_MICROSOFT_SSO_ENABLED=true
BATUK_MICROSOFT_PROVIDER_ID=microsoft-entra
NEXT_PUBLIC_BATUK_MICROSOFT_PROVIDER_ID=microsoft-entra
NEXT_PUBLIC_BATUK_MICROSOFT_SSO_LABEL=Continue with Microsoft
BATUK_MICROSOFT_TENANT_ID=replace_with_directory_tenant_id
BATUK_MICROSOFT_CLIENT_ID=replace_with_application_client_id
BATUK_MICROSOFT_CLIENT_SECRET=replace_with_client_secret_value
BATUK_MICROSOFT_DOMAIN=example.edu,example.com
BATUK_MICROSOFT_SCOPES=openid,profile,email,offline_access
```

Nutze eine echte Microsoft Directory Tenant ID, damit die OIDC-Issuer-Validierung strikt bleibt. `BATUK_MICROSOFT_DOMAIN` akzeptiert eine oder mehrere komma-getrennte E-Mail-Domains, was besonders für Universitäten und europäische Organisationen mit mehreren Domains nützlich ist.

### Administration und Governance

Admins können AI-Zugriff und Workspace-Verhalten ohne Codeänderungen verwalten.

- First-owner Bootstrap, wenn noch kein Owner oder Admin existiert.
- Benutzer CRUD, Passwort-Resets, Bans, Unbans und Löschung.
- Organisationserstellung und Wechsel der aktiven Organisation.
- Teamerstellung, Einladungen und Rollenmanagement.
- Erstellung geteilter Workspaces, Mitgliedschaft, RAG-Aktivierung, Umbenennung und Löschung.
- Token Usage Dashboard nach Quelle, Anbieter, Modell, Benutzer, Chat, API Key, Tag, Monat und Jahr.
- Audit Trail für Access Denials, Admin-Aktionen, Dokumentoperationen, Chat-Library-Mutationen, Datenschutzanfragen und Control Changes.
- Hash-Chain-Integritätsnachweise für Audit Events.
- GDPR Export-, Request- und Erasure-Workflows.
- ISO 27001 und SOC 2 Control Evidence Register.

### Internes AI API Gateway

Batuk erlaubt Benutzern, persönliche API Keys zu erzeugen und von Admins freigegebene Modelle über OpenAI-kompatible Endpunkte aufzurufen. Dadurch ist Batuk nicht nur ein AI Chat Workspace, sondern auch eine interne Modellzugriffsschicht für Business Apps, Automatisierung und Agent Workflows.

```bash
curl -H "Authorization: Bearer batuk_..." http://localhost:3000/api/v1/models

curl -X POST http://localhost:3000/api/v1/chat/completions \
  -H "Authorization: Bearer batuk_..." \
  -H "Content-Type: application/json" \
  -d '{"model":"company/support-large","messages":[{"role":"user","content":"Hello"}]}'
```

API Keys sind benutzergebunden und werden als Hashes gespeichert. Admins können Routen wie `company/support-large` oder `batuk/qwen3.7-max` bereitstellen, die auf einen in Batuk konfigurierten Provider, ein Modell und eine Base URL zeigen. Nutzung wird getrennt für Chat, API Completions und Search aufgezeichnet.

## Storage, RAG und Deployment-Optionen

Batuk ist bewusst modular. Teams können mit lokalem Speicher beginnen und bei wachsender Nutzung auf Enterprise-Infrastruktur wechseln.

| Ebene | Standard | Enterprise-Optionen |
| --- | --- | --- |
| Authentifizierung | SQLite | SQLite, MySQL, PostgreSQL, MS SQL, MongoDB |
| Produktdaten | Lokales JSON | SQLite, MySQL, PostgreSQL |
| Dokumente | Lokaler Dateispeicher | Konfigurierbarer lokaler oder Container-Pfad |
| Branding-Logos | `public/branding` | Konfigurierbarer lokaler oder Container-Pfad |
| Vektoren | Lokales JSON | ChromaDB, Pinecone, Qdrant Cloud, Supabase pgvector |
| Advanced Document Intelligence | Eingebaute Textextraktion | Optionales FastAPI Backend, Graph RAG, Neo4j |

Produktdaten umfassen Chats, Ordner, Workspaces, Dokumentmetadaten, Chunks, Memories, API Keys, Modellrouten, Skills, MCP-Integrationsdaten, Agents, Workflows, Token-Nutzung, Branding, Compliance-Datensätze, GDPR-Anfragen und Audit Trails.

Persönliche Produktdaten sind auf den angemeldeten Benutzer beschränkt. Geteilte Workspace-Daten sind auf den Workspace beschränkt und werden erst nach Membership- oder Admin-Prüfung geladen.

## MCP Integrationen

Batuk enthält ein MCP Dashboard, um Tools, Ressourcen und Prompts mit dem Workspace zu verbinden. Teams können streamable HTTP, SSE und stdio MCP Server registrieren, Capabilities entdecken, Ressourcen prüfen und eine aktive MCP Integration als Chat-Kontext auswählen.

Vordefinierte Connector-Kategorien umfassen Productivity, CRM, Payments, Analytics, Project Management, Databases, Search, Browser Automation, Developer Tools und eigene interne MCP Server. Batuk redigiert gespeicherte Client Secrets und Tokens, bevor MCP-Integrationskonfigurationen an den Browser zurückgegeben werden.

MCP macht Batuk zu mehr als einer Chat-Oberfläche: Es kann ein verwalteter AI Workspace werden, in dem Modelle, Dokumente, Tools und Enterprise-Systeme unter Admin-kontrolliertem Zugriff zusammenkommen.

## Quick Start

```bash
npm install
npm run dev
```

Öffne `http://localhost:3000`, erstelle ein Konto, wähle in Settings einen Provider und ein Modell und starte den Chat.

Lokale Ollama-Nutzung:

```bash
ollama pull llama3.1
ollama serve
```

Danach in Batuk den Ollama Provider auswählen.

Ollama RAG Embeddings:

```bash
ollama pull embeddinggemma
```

Danach im Documents Panel `Ollama embeddings` auswählen und das Embedding Model auf `embeddinggemma`, `qwen3-embedding`, `all-minilm`, `nomic-embed-text`, `mxbai-embed-large` oder ein anderes lokal gepulltes Ollama Embedding-Modell setzen.

## Selbst gehostetes Deployment

Batuk enthält Docker- und Datenbank-Assets für selbst gehostete Enterprise-Umgebungen.

```text
Dockerfile
docker-compose.yml
.env.enterprise.example
database/sqlite/001_enterprise_data.sql
database/postgresql/001_enterprise_data.sql
database/mysql/001_enterprise_data.sql
```

Runtime-Umgebungsdatei erstellen und Stack starten:

```bash
cp .env.enterprise.example .env.enterprise
docker compose up --build
```

Optionale Service-Profile bei Bedarf aktivieren:

```bash
docker compose --profile postgres up --build
docker compose --profile mysql up --build
docker compose --profile postgres --profile chroma up --build
docker compose --profile ollama up --build
docker compose --profile advanced-rag up --build
docker compose --profile advanced-rag --profile neo4j up --build
```

Deployment Buttons für Vercel, Render und Railway sind verfügbar. Docker Compose ist der bevorzugte Weg für Teams, die private SQL-Services, lokale Vektorsuche, kontrollierten Dateispeicher, lokale Modelle, Advanced RAG oder internes Netzwerk-Deployment benötigen.

## Konfiguration

Diese Dateien sind die operative Source of Truth:

- `.env.enterprise.example` für Identity, Modellanbieter, SQL Stores, Vektor Stores, Dateipfade und Runtime-Verhalten.
- `docker-compose.yml` für PostgreSQL, MySQL, ChromaDB, Ollama, Advanced RAG FastAPI und Neo4j Profiles.
- `optional-backend-for-advanced-rag/README.md` für das optionale Python Backend.
- `database/*/001_enterprise_data.sql` für Produktdaten-Schemas.

Nützliche Befehle:

```bash
npm run auth:migrate
npm run data:migrate
npm run env:validate
```

## Scripts

```bash
npm run dev           # Lokale Entwicklung starten
npm run build         # App bauen
npm run start         # Server starten
npm run lint          # ESLint ausführen
npm run env:validate  # Enterprise-Umgebung validieren
npm run auth:migrate  # Better Auth Schema erstellen/aktualisieren
npm run data:migrate  # Batuk Produktdaten-Schema erstellen/aktualisieren
```

## Testbefehle

```bash
npm run test:unit         # Unit Tests
npm run test:integration  # Integration Tests
npm run test:e2e          # Next.js HTTP Smoke Test
npm run test:load         # Gleichzeitige HTTP Load Checks
npm run test:security     # Security Headers und geschützte API Checks
npm run test:regression   # Lint, Unit, Integration und Build Gate
npm run test:all          # Vollständige Validierung
```

## Projektstruktur

```text
app/                  Next.js app routes and API endpoints
components/           Chat, docs, enterprise, audit, settings, skills, MCP, agents
hooks/                Chat controller and UI state orchestration
lib/                  Providers, auth, RAG, MCP, storage, compliance, branding
database/             SQLite, PostgreSQL, and MySQL product data schemas
scripts/              Migration and Docker startup helpers
tests/                Unit, integration, E2E, load, security, and regression gates
data/                 Local runtime data in development
public/branding/      Uploaded organization logos
```
